# FluentRead v0.0.38 — openai responses

Published by the [windsyu/FluentRead fork](https://github.com/windsyu/FluentRead), not an official upstream store release. Extension version: `0.0.38`. Userscript version: `2.0.2`.

## Changes

- Added the independent `openai responses` translation provider for official Responses endpoints and compatible self-hosted New API servers. Existing OpenAI, New API, and custom Chat providers retain their protocols and configuration.
- Normalized root URLs, version bases, and complete endpoints consistently for requests, credentials, and cache identity; preserved query parameters and added a correction message for `/response`.
- Built native `instructions` and array `input`, enforced `stream: true` and `store: false`, rejected custom `messages`, and removed unsupported sampling/output-limit fields.
- Shared fragmented UTF-8/SSE parsing between connection checks and translation. Only a valid completed response produces a full translation; failed, incomplete, or interrupted streams do not produce partial success.
- Fixed connection checks being invalidated by same-value configuration broadcasts while preserving isolation on real configuration changes, deactivation, and cancellation.

Download assets from the fork's [v0.0.38 Release](https://github.com/windsyu/FluentRead/releases/tag/v0.0.38):

| Asset | Purpose |
| --- | --- |
| `fluent-read-0.0.38-chrome.zip` | Extract and load in Chrome developer mode |
| `fluent-read-0.0.38-edge.zip` | Dedicated Edge build without the Chrome manifest key; extract and load in developer mode |
| `fluent-read-0.0.38-firefox.zip` | Temporary Firefox loading/review; unsigned by AMO, not a normal store installation package |
| `fluent-read-0.0.38-sources.zip` | Extension build/review sources; the complete repository is also available at the release tag |
| `fluent-read.user.js` | Userscript `2.0.2`; execution in a real script manager remains unverified |
| `SHA256SUMS-v0.0.38.txt` | SHA-256 checksums for the download assets |

For Chrome/Edge, extract the ZIP, enable developer mode on the extensions page, and load the extracted directory. Select `openai responses` in settings and enter your endpoint, model, and Key. This provider does not share other providers' credentials; existing users must configure it separately. The official default is `https://api.openai.com/v1/responses`; self-hosted servers may use a root URL. Do not place secrets in advanced request bodies, public logs, or source control.

## Validation and limitations

- Passed 405 protocol/configuration tests, 984 regression tests, 21 release metadata/manifest tests, the test audit, and type checking on the new version.
- Built and verified Chrome, Edge, Firefox ZIPs and the userscript. An isolated Chrome/local SSE fixture passed eight cases, including existing Chat behavior.
- Before the version bump, the production Chrome extension successfully used the authorized real New API server for connection checks and fresh webpage translations with root, `/v1`, and complete `/v1/responses` URLs. The final live run had 16 successful SSE requests and one expected 401; restore/retranslate, saved configuration reopening, and retry after restoring the valid Key passed. The production change for release is version metadata only; no additional real-provider requests were made.
- Navigation cancellation prevented late translation insertion and the next request succeeded, but an early upstream socket abort was not observed. Offline tests cover reader/listener/scheduler cleanup and timeouts.
- Real Firefox and userscript-manager execution remain unverified. Unrelated full-repository failures were reproduced on the unchanged baseline, so this is not a claim that every repository test passes. See the [redacted acceptance report](https://github.com/windsyu/FluentRead/blob/v0.0.38/docs/reports/openai-responses-20261010.md) for details and coverage boundaries.

This release does not add assistant conversations, tool calling, image recognition, or progressive text display. Assets contain no user credentials, live configuration, browser profiles, or raw live-test evidence. No browser-store submissions were made.
